  Upload → ImageKit → Build Payload → Pinata/IPFS → Database

  🔧 Recommended Production Flow:

  For Media Files:

  1. Upload to ImageKit (primary storage)
  2. Get ImageKit URL + optimizations (thumbnail, webp, etc.)
  3. Background job: Pin to IPFS via Pinata
  4. Insert to database with both URLs

  For Metadata JSON:

  1. Build metadata payload
  2. Upload JSON to Pinata → IPFS
  3. Insert metadata to database with IPFS URL
  4. Optional: Cache JSON in ImageKit for faster access

  💡 Key Changes cho production:

  1. Async IPFS pinning - Không block user upload
  2. ImageKit as primary - Faster CDN delivery
  3. IPFS as backup/permanence - Blockchain standard
  4. Separate flows - Media vs Metadata có requirements khác nhau

  Real-world Example:

  // Media upload
  POST /media/upload
  → ImageKit upload (immediate)
  → Return ImageKit URL to user
  → Background: Pin to IPFS
  → Update DB with IPFS URL when ready

  // Metadata creation  
  POST /metadata
  → Build JSON payload
  → Pin JSON to IPFS (fast for JSON)
  → Store in DB with IPFS URL
  → Optional: Cache in ImageKit
